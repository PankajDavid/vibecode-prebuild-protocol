# Prompt 1 — Fill in the documents

Use this once per document, in order (1 → 2 → 3 → 4 → 5). Attach or paste the template, plus every document you've already approved.

Replace everything in `[brackets]`.

---

### First time (Document 1)

```
I'm using the Vibecode Pre-Build Protocol. I've attached the template for Document 1 (Product Requirements).

My product idea: [one paragraph — what it does, who it's for, the problem it solves]

Fill in Document 1 only.
Rules:
- Before writing, ask me up to 5 questions about anything you'd otherwise have to guess.
- Where you don't know something, write "Unknown". Don't invent numbers, users or facts.
- Keep the Non-Goals section honest and specific. Tell me what I should NOT build in the first version.
- Use plain English.
Stop after Document 1 and wait for my approval.
```

### Every document after that (2, 3, 4, then 5)

```
Document [number] is approved. I've attached the approved documents [list them] and the template for Document [next number] ([name]).

Fill in Document [next number] only.
Rules:
- It must agree with every approved document. If something in an earlier document seems wrong, tell me — don't silently change it.
- Every decision needs a reason written next to it.
- Ask me up to 5 questions first about anything you'd otherwise guess.
- Write "Unknown" rather than inventing facts. For the Compliance section in Document 3, leave anything you're not sure of blank.
- Use plain English.
Stop after this document and wait for my approval.
```

### Extra line for Document 5 (Feature Tickets)

Add this to the prompt above when you reach Document 5:

```
Each ticket must be small enough to build and check in one session. List tickets in the build order from Section 4. For every ticket, list which Absolute Rules from Document 3 apply.
```
